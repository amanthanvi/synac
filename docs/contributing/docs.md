# Contributing: documentation

Docs changes are one of the most valuable contributions. If something feels unclear or “robotic”, fix it.

## Tone

Follow `docs/voice.md`.

## Writing guidelines

- Assume the reader is competent and busy.
- Prefer checklists for procedures.
- Link to the source of truth instead of duplicating it.
- Keep docs short. If a file gets long, split it.

## Where docs live

- Repo front door: `README.md`, `CONTRIBUTING.md`, `SECURITY.md`
- Project docs: `docs/**`
- Product/spec: `SPEC.md` (source of truth for intended behavior)
- Execution tracker: `PLAN.md` (implementation tracker)

## Screenshots in docs

If a screenshot materially helps:

- Keep it cropped and legible.
- Prefer PNG.
- Store under `docs/assets/`.
- Reference it from Markdown with a relative path (e.g. `docs/assets/readme-home.png`).
