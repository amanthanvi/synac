# SynAc voice + writing guidelines

SynAc is a reference product. Writing should feel like it was written by a careful human who’s been on-call.

## Principles

- Prefer **clarity over cleverness**.
- Prefer **concrete nouns** over abstractions.
- Prefer **short sentences**. If it’s complex, split it.
- Avoid hype. Avoid “world-class”, “revolutionary”, “seamless”, “just”.
- Don’t anthropomorphize the system (“SynAc thinks…”).
- Define a term once, then use it consistently.
- If a statement is a claim, attach a source or scope it (e.g. “in this codebase”, “in v0.1.x”).

## Repo docs tone

- Assume the reader is capable and busy.
- Use checklists for procedures.
- Put the “why” first, then the “how”.
- Prefer “Do X” over “You should do X”.
- When something is out of scope, say so explicitly and link to where decisions are made.

## UX + UI text

- Use practitioner language (“runbook”, “incident”, “blast radius”, “source of truth”).
- Avoid cute microcopy.
- Keep headings specific (no “Overview” / “Stuff” / “Things”).
